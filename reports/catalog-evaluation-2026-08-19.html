Every skill now improves its paired task.

After repairing the evaluator and revising the skills one by one, the latest applicable paired evidence shows a treatment win for all 17 catalog skills. The result is encouraging, but it is still a small benchmark—not proof that every future request improves.

17 wins

Measured: equal-weight per-skill quality rises from 2.53/4 without skills to 3.56/4 with skills, a 40.7% relative increase on this benchmark.

Confidence boundary: six initially unstable or tied skills received two-epoch confirmation. The other eleven have current single-run paired wins. Generation and grading used the same model family, so independent adjudication and additional models remain valuable.

What changed

Made the evaluator factual

The grader now sees diffs, required and untracked artifacts, and bounded command output. It uses a 0–4 quality scale instead of an all-or-nothing pass.

Separated content from routing

Treatment injects the exact selected skill verbatim. Installation and routing are separate smoke concerns, so a reserved .system path cannot invalidate an efficacy result.

Removed hidden requirements

Required filenames are now visible in prompts. Ceiling cases were replaced with realistic tasks whose distinctive quality comes from the skill rather than a leading prompt.

Improved the skills

The revisions sharpen exact acceptance contracts, one-shot grilling, destructive gates, review evidence, two-identity authorization tests, teaching transfer, verification layers, historical-change evidence, factual rewriting, HTML data integrity, and lean workflow construction.

Fixed an overcomplicated skill

create-workflow initially made results worse by generating elaborate validators. It was simplified to prefer one narrow artifact, only required branches, temporary test fixtures, and observed evidence.

How to read this result

Supported: on the current representative cases, following every catalog skill produced a higher mean quality score than the no-skill condition.

Not supported: that every invocation will improve, that the deltas generalize to every model, or that the 0.5-point wins are statistically stable. The benchmark was iteratively improved using observed failures, so a future hidden holdout set is the next protection against overfitting.

Next evaluation step: freeze these cases as development tests, add unseen holdouts for the highest-value skills, and run three or more paired epochs with an independently chosen grader model before removing or retaining skills solely from scores.
