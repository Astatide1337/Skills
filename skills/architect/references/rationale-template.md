# Design rationale

Use these optional prompts for a decision whose reason is not obvious. Put the
relevant answers in the existing task record or requested artifact; no separate
file is required.

## Problem

What outcome and constraints make this decision difficult?

## Usage

Show the caller's imports, calls, inputs and outputs.

## Shape

Define the data, public signatures, module ownership, validation and invariants.
State which complexity the interface hides.

## Decision

Name the chosen design and why it fits the requirements.

## Tradeoffs and alternatives

Explain the tradeoffs and credible alternatives that affected the choice.

## Risks and next step

List open questions and the first implementation step.
