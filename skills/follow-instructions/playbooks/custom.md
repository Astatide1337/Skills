# Custom / compose a temporary process

## When

Use only when the user explicitly requests a bespoke process or no existing
playbook/composition can express the required dependency. A novel technology,
unfamiliar language, or a failed known route is not enough.

## Inputs to establish

- requested outcome, literal constraints, authority, source/environment and
  how success will be judged;
- existing playbooks/domain skills that apply and the concrete uncovered
  dependency or decision;
- unknown facts that can be inspected versus product/risk choices requiring
  the user.

## Steps and decision points

1. Try the closest existing route and composition first. Inspect real inputs
   and capabilities; do not plan around imaginary endpoints or tools.
2. Put a compact temporary task list in the existing task record:
   `step / reused method or tool / observable result / failure decision`.
3. Resolve costly or irreversible unknowns before action. Build a helper only
   when existing tools cannot make the needed observation. Execute one unit at
   a time and preserve original constraints/authority.
4. Verify the combined result and requested publication, then leave the recipe
   temporary. A recurring pattern may later use `workflow-improvement`, but it
   does not become a permanent skill by default.

## Failure and recovery

If a required input/capability is unavailable, complete independent work and
report the precise blocker. Do not weaken acceptance, bypass security or
verification, or reroute a failed known playbook merely to avoid its gate.
Change the temporary sequence when observations invalidate it and disclose the
material deviation.

## Completion evidence

Return the original outcome, temporary steps, observed artifacts/behavior,
failure decisions, publication/readback evidence, and remaining uncertainty.
No custom runtime, scheduler, state database, or permanent framework is proof
of success.

## Example

Build an offline reproduction package from authorized sanitized snapshots by
reusing investigation, security, implementation, verification, and teaching;
exercise it in disposable state and deliver only the requested package.

## Near-miss

“Fix this Python bug” is not custom merely because the syntax is unfamiliar;
use `implement/bug` and the existing debugging method.
