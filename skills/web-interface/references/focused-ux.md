# Focused UX improvement

Use the smallest relevant lens for an observed interface problem. Preserve the
project's design system and the user's accepted choices.

- **Critique:** observe the real journey and explain where hierarchy, affordance,
  density or feedback obstructs the task. Distinguish evidence from preference.
- **Clarify:** make action labels, instructions, validation and recovery copy
  specific to the user's goal. Keep necessary consent and safety information.
- **Harden:** exercise empty/loading/error states, long content, failed images,
  keyboard focus, retries and input preservation relevant to the change.
- **Adapt:** inspect the affected viewport/input modes and themes. Resolve
  clipping and unusable interactions without introducing a new visual language.

Use only the lens that answers the present question. Automated axe or framework
diagnostics complement observed keyboard and interaction checks; they don't
replace them. Keep one actionable findings set and verify the corrected journey.

Method provenance: original synthesis informed by
[Impeccable](https://github.com/pbakaus/impeccable)'s focused design procedures.
No upstream prompts or complete command suite are vendored.
